# ADR-0012 CI/CD パイプライン

- ステータス: 承認
- 日付: 2026-11-28

## 背景
ネイティブエンジンのビルドには 1 時間ほどかかる。端末での検査はエミュレータを使うため重く、1 台のランナーでは資源が尽きた。
リリースでは署名と、AGPL に従ったソースとライセンスの提示が要る。

## 決定
GitHub Actions で、検査とリリースを次の流れにする。

### 共通: ネイティブエンジン
- `native.yml` を再利用できるワークフローにし、CI とリリースの両方から呼ぶ。
- レシピ、版、共通設定のハッシュをキーに `native/out` をキャッシュする。変更が無ければビルドしない。
- 成果物は `native-out` として後続のジョブに渡す。

### CI: プルリクエストと main
- `android-build`: ビルド、単体テスト、Lint、依存方向の検査。
- `device-tests`: モジュールごとにランナーを分け、API 31 と 37 のエミュレータで計装テストと E2E を回す。
- `emulator-tests`: 全モジュールの結果をまとめる。ブランチ保護ではこれと `android-build` を必須にする。
- 必須チェックが通れば自動でマージする。

### CD: タグ
- `v` で始まるタグを push すると `release.yml` が動く。
- 全検査を通してから、シークレットの署名鍵でリリース版の APK を作り、署名を検証する。
- 版名はタグから、版番号は実行番号から付ける。
- GitHub Releases に APK とライセンス一覧を公開し、対応するソースの入手先を記す。

## 結果
エンジンを変えない限り、CI は数十分で終わる。
署名鍵は 4 つのシークレットで渡す。ANDROID_KEYSTORE_BASE64、ANDROID_KEYSTORE_PASSWORD、ANDROID_KEY_ALIAS、ANDROID_KEY_PASSWORD である。
シークレットが無いと、リリースは署名の段階で失敗する。
