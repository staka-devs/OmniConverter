# ADR-0005 ネイティブエンジンは Docker 上でソースからビルドする

- ステータス: 承認
- 日付: 2026-11-27

## 文脈
FFmpeg や ImageMagick の既製バイナリは、入手元や組み込まれたライブラリ、ライセンス上の扱いがまちまちである。
また、開発者の手元の OS によってビルド結果が変わると、不具合の再現が難しくなる。

## 決定
すべてのネイティブエンジンを、Docker コンテナの中でソースからビルドする。

- コンテナは `native/Dockerfile` で定義する。Ubuntu 24.04 に NDK r30 とビルド用ツールを入れる。NDK は SHA-1 で検証する。
- ソースの版と SHA-256 は `native/versions.sh` だけで管理する。取得時に必ず検証する。
- ビルド手順はエンジンごとに `native/recipes/<名前>.sh` に書く。共通の設定と補助関数は `native/lib/common.sh` に置く。
- ホストからは `native/run.sh <名前>` で実行する。成果物は `native/out/<エンジン>/arm64-v8a/lib<実行ファイル名>.so` に出る。
- 依存ライブラリは静的にリンクする。C++ 標準ライブラリも静的に入れる。実行ファイルは Android 標準の共有ライブラリだけに依存させる。
- 成果物は検査してから置く。aarch64 の PIE であること、許可した共有ライブラリにしか依存しないことを確かめる。
- 16 KB ページの端末でも読み込めるよう、ページ境界を揃えてリンクする。
- 成果物とソースは git で管理しない。

## 結果
誰が実行しても同じ手順でエンジンを作れる。どのライブラリをどの版で入れたかがリポジトリから追える。
初回のビルドは時間がかかるため、CI ではキャッシュが必要になる。
