# ADR-0003 エンジン共通 API とプラグイン方式

- ステータス: 承認
- 日付: 2026-11-27

## 背景
FFmpeg、ImageMagick、libheif、libarchive、MuPDF、pandoc は、扱う形式も呼び出し方も異なる。
画面や一括変換の処理が個々のエンジンを知っていると、エンジンを追加するたびに広い範囲を直すことになる。

## 決定
Domain に共通インターフェース `ConversionEngine` を置き、すべてのエンジンがこれを実装する。

- 各エンジンは自分が扱える入力形式と出力形式の組を `Capability` として宣言する。
- 変換は `convert` で行う。上級モード用に、引数をそのまま渡す `runRaw` も持つ。
- エンジンは 1 つにつき 1 モジュール `:infrastructure:engine-<名前>` とする。
- Application は宣言された能力から変換経路を選ぶ。直接変換できないときは 2 段までつなぐ。
- エンジンの追加は、モジュールを作り、`:app` で登録するだけで済むようにする。

## 結果
画面と一括変換の処理は、どのエンジンが使われるかを知らない。
エンジン固有の細かい指定は、上級モードの生コマンドで補う。
共通 API に収まらない機能は、`Capability` のオプション定義で表現する。
