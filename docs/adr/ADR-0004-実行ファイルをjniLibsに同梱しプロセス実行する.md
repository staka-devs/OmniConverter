# ADR-0004 実行ファイルを jniLibs に同梱しプロセス実行する

- ステータス: 承認
- 日付: 2026-11-27

## 文脈
各エンジンは CLI として最もよく整備されている。ffmpeg、magick、bsdtar、mutool、pandoc の引数をそのまま使えれば、上級モードも素直に作れる。
一方で JNI で各ライブラリを呼ぶと、エンジンごとに C の結合コードが必要になる。またクラッシュがアプリ全体を落とす。

Android 10 以降は、アプリが書き込める場所にあるファイルを実行できない。

## 決定
エンジンは CLI の実行ファイルとして組み込み、別プロセスで実行する。

- 実行ファイルは `lib<名前>.so` という名前で各エンジンモジュールの jniLibs に置く。
- `useLegacyPackaging` と `extractNativeLibs` を有効にし、インストール時に nativeLibraryDir へ展開させる。この場所は実行が許可されている。
- 起動は `NativeProcessRunner` が受け持つ。標準出力と標準エラーをまとめて読み、末尾のログだけを保持する。
- 呼び出し元のコルーチンがキャンセルされたら、プロセスを強制終了する。

## 結果
エンジンがクラッシュしても、アプリは失敗として扱える。
エンジン固有のコードは、引数の組み立てと進捗の読み取りだけで済む。
APK の圧縮が効かないため、インストール後のサイズは大きくなる。
共有ライブラリを持つ実行ファイルは、同じディレクトリから読めるように `LD_LIBRARY_PATH` を渡す必要がある。
